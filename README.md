# CQA

**Команда: team vasya.** Проект для **Data Challenge Hackathon**.

Сервис для проверки качества переписки с поддержкой. Он оценивает работу оператора по чек-листу, объясняет оценки и показывает, какие сообщения их подтверждают. Если оценка спорная, можно подать апелляцию.

Интерфейс написан на HTML, CSS и JavaScript. Сервер работает на Python.

## Запуск

Нужен Python 3.10 или новее. Откройте PowerShell в папке проекта и выполните:

```powershell
powershell -ExecutionPolicy Bypass -File .\start.ps1
```

Скрипт установит зависимости и запустит сервер.

- [Открыть приложение](http://127.0.0.1:8000/)
- [Документация API](http://127.0.0.1:8000/docs)

Для остановки нажмите `Ctrl+C` в окне сервера.

## Подключение модели

Сохранённые диалоги и оценки можно смотреть без модели. Для новой оценки подключите один из сервисов в файле `.env`:

- **Ollama:** `CQA_PROVIDER=ollama`. В `CQA_MODEL` укажите имя установленной модели.
- **Groq:** `CQA_PROVIDER=groq`. Укажите доступную модель в `CQA_MODEL` и ключ в `GROQ_API_KEY`.

Пример настроек — в `.env.example`. После изменения `.env` перезапустите сервер. Ключи из `.env` не добавляйте в Git.

## Как пользоваться

В `.env` укажите ссылку организаторов в `CQA_DATASET_URL`. Она содержит подпись доступа, поэтому не публикуйте её. При пустой базе DEV загрузится из API автоматически при открытии диалогов. Это не запускает оценку моделью. Существующие наборы читаются из базы; для повторной загрузки нажмите **Данные → Загрузить из API**. Оценки и апелляции сохраняются. Если исходные реплики изменились, импорт отклоняется, чтобы не подменить доказательства старых оценок.

`CQA_DATASET_GROUP_ID=DEV` задаёт группу для автоматической загрузки, `CQA_AUTO_IMPORT=false` отключает её. Для PROD укажите ID контрольной группы в форме импорта. Ошибки доступа и сети показываются в интерфейсе; JSON-импорт остаётся доступен.

В разделе **Данные** кнопка **Загрузить FBroker** получает 10 контрольных чатов в PROD. Затем запустите пакетную оценку с официальным чек-листом. **Сохранить SWAP без оценки** загружает дополнительный набор отдельно: он не оценивается и не входит в PROD. Экспорт запускается только кнопкой скачивания, после проверки результатов.

1. В разделе **Данные** загрузите JSON с диалогами.
2. В разделе **Диалоги** откройте переписку, выберите чек-лист и запустите оценку.
3. Посмотрите результат по каждому критерию. Ссылки на реплики ведут к нужным сообщениям.
4. Если не согласны с оценкой, подайте апелляцию. Решение эксперта сохраняется в истории.
5. В разделе **Данные** выгрузите результаты в JSON.

Текущая оценка учитывает решения эксперта. Исходная AI-оценка остаётся в истории. Критерии с `N/A` не участвуют в расчёте общего балла.

## Где что находится

- `static/` — страницы, стили и код интерфейса.
- `cqa/` — сервер и логика оценки.
- `data/cqa.sqlite3` — диалоги, оценки и апелляции. Папка `data/` не входит в архив для передачи.
- `tests/` — проверки серверной логики.

## Проверки

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
.\.venv\Scripts\python.exe -m pytest -q
```

Тесты проверяют логику сервера без запросов к настоящей модели. Сведения о шрифтах — в [FONT-NOTES.md](FONT-NOTES.md), лицензия эффектов — в `static/vendor/react-bits/`.

В GitHub добавляйте исходники и `.env.example`. Локальные `.env`, `data/` и `.venv/` исключены через `.gitignore`.

Это локальный прототип без авторизации. Оценки модели требуют проверки человеком.
